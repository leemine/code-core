## 背景

Shell 底层支持 environment，但 BashTool 未透传。依赖修改进程环境传递连接器凭据会
污染同进程其他会话，且还原全局环境不能解决并发重叠。

## 数据与生命周期

工具持有可选同步 environment_provider 回调，不持有持久密钥映射。原权限检查之后，
每次真正启动 Shell 前解析并复制映射；普通、流式、后台均使用原执行器和取消路径。
不存在新的执行队列、权限表或身份模型。宿主可以在回调内检查当前原始执行上下文，
但该回调不取代工具权限引擎，也不声明任意 Shell 的 OS 隔离。

## 决策

- 参数只在工具构造时注入，不增加模型可见参数，不扩展 create_deep_agent。
- SysOperationRail 的可选 bash_environment_provider 复用既有注册路径，初始化不调用回调。
- 未注入时不新增底层关键字，保留旧 Shell 实现/测试替身兼容。
- 仅接受字符串键值映射，拒绝无效环境名和 NUL；复制后传递，避免调用者后续修改。
- 失败不回退父环境执行，不暴露回调异常、凭据或映射内容。
- 父环境仍由底层 Shell 按原行为合并；宿主负责确保其中没有其他主体的凭据。

## 拒绝的方案

不写 os.environ，不用进程锁包裹临时环境切换；不把身份/组织策略放入 Core；不让模型
通过工具参数提交环境变量，不复制 Shell 执行或取消实现。

## 验证

本地使用隔离 HOME/TMPDIR、真实本地 SysOperation 子进程验证普通、流式、后台、
并发环境及撤权后禁止启动；Bash/Shell、Rail 和内置子代理受影响测试共 169 项通过。
strict stable 2261 项通过，失败、错误、超时、跳过、阻塞均为零。
首次 strict 启动因 sudo 密码要求记录为 11 组 blocked；随后使用非特权 bubblewrap，
保持 strict 网络隔离和原超时重跑通过。CI 对最终提交运行相同 strict 和新增受影响测试。

make check 仍报告触及旧文件原有格式及 os.path.isdir 的 ASYNC240；没有增加忽略项，
未按本改动触发旧文件全面格式化。新增测试通过 ruff。测试环境未安装 codespell，
拼写检查尚未执行。此前 /tmp 接口原型不是本特性产品验收。

## 已知遗留

宿主需把回调接入其工具装配；活动后台进程的停止与权限撤销仍归原生命周期。
PowerShellTool/CodeTool 未增加此参数，不推断它们具备相同能力。
